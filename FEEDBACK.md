# Feedback and bug reports

Use [GitHub Issues](https://github.com/KaalBrown/ximple-explorer/issues/new/choose) for a bug report, usability feedback or feature request. You can also reply to a community announcement. Downloading the app requires no account; GitHub and community sites apply their own account requirements for posting.

One report per problem makes follow-up easier. Search existing issues first if convenient; a duplicate is preferable to an unreported file-operation failure.

## What helps

Include the app and Windows versions, the action you took, the expected result and the actual result. For visual problems, add your theme and display scaling. For file-operation problems, identify the storage type and whether the problem is repeatable using disposable files.

Screenshots are optional. Please remove private filenames, addresses, document contents, tokens and other personal information before posting. Do not attach irreplaceable files. Public issues and comments can be read by anyone.

## How reports will be handled

1. **File-operation failures and crashes:** investigate first. If a report suggests possible data damage, pause wider promotion and establish a reproduction before expanding testing.
2. **Broken navigation and usability:** reproduce in the relevant pane, view, theme and display scale.
3. **Feature requests:** record the task the feature would help with, then weigh it against the goal of a small, straightforward explorer.

Reports can be marked with the default `bug`, `enhancement`, `question`, `duplicate` or `invalid` labels as appropriate. A fix should reference the affected report, name the preview version containing it and invite the reporter to retest. Close the report after verification or with a clear explanation of the outcome.

Preview updates will be published under [Releases](https://github.com/KaalBrown/ximple-explorer/releases), with short notes describing what changed. Acknowledgement and fixes are best-effort; no response-time or release-date promise is made.
